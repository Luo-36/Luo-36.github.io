一、仓库初始化 & 远程关联

1. git init

作用：当前目录创建本地Git仓库，生成隐藏 .git 文件夹
参数：无
使用：进入项目根目录执行，一个本地仓库只运行一次。

2. git remote

  • origin：远程仓库别名，约定俗成固定叫origin
  • <远程仓库地址>：Github仓库 HTTPS / SSH链接

二、文件暂存、提交（日常开发核心）

1. git status

作用：查看工作区文件状态（新增/修改/删除，是否加入暂存）
参数

  • --short / -s：精简输出，只显示状态码+文件名

2. git add

作用：文件从工作区加入暂存区(stage)，.gitignore 里的文件自动跳过

  • . ：当前目录全部文件，递归所有子文件夹
  • <文件名>：单独添加指定文件，例：git add User.java
  • <文件夹>/：添加整个文件夹

⚠️ add只是放到暂存，还没有提交到本地仓库

3. git commit

  • -m "备注"：必填，填写本次改动描述，清晰记录修改内容

  • --amend：修改上一次commit，覆盖上一条提交记录。适合备注写错、漏add文件>

    示例：git commit -m "新增Lombok User实体类"

三、拉取 / 推送远程Github

1. git fetch

作用：只下载远程分支、提交记录，不会修改本地文件，不会自动合并

  • origin：远程仓库别名
  • -p = --prune：修剪，删除本地缓存中远程已经不存在的分支（清理origin/main用这个）

2. git pull

等价 git fetch + git merge，拉取远程master分支并且合并到当前本地分支

  • origin master：拉取origin远程的master分支

  • --rebase：变基合并，提交记录为一条直线，多人协作常用>

    单人仓库几乎不用pull，多人协作才需要

3. git push

  • git push origin master：本地master分支推送到远程origin/master，日常上传代码
  • -f / --force ⚠️强制推送：本地分支直接覆盖远程提交历史。多人项目禁止！仅首次全量替换代码
  • --delete：删除远程分支，git push origin --delete main 删除远程main分支

四、分支操作

1. git branch

示例：git branch -D main 删除本地废弃main分支

2. 切换分支

作用：切换本地分支，会替换当前文件夹内文件！切换前最好commit保存改动
示例：git switch master

3. 创建并且直接切换到新分支

  • -c = create，创建分支并立刻切进去

4. 合并分支

  • --allow-unrelated-histories：合并两条完全没有共同提交历史的分支（你之前main/master场景）>

    操作流程：切到目标分支(master) → git merge 别的分支 → 解决冲突 → commit → push

五、查看提交日志

  • git log：完整提交日志，作者、时间、完整commit哈希
  • --oneline：单行精简输出，7位短hash+提交备注（最常用）
  • --graph：绘制分支图形，直观查看分叉合并关系

六、.gitignore 相关：移除已经提交过的文件

场景：文件已经提交进git，之后想加入ignore。只写.gitignore无效，要从git缓存移除，保留本地文件

  • --cached：只从git版本库/缓存删除，电脑本地文件保留
  • -r：递归，用于文件夹，例如 target、.idea
    例子：git rm -r --cached project1/target

⚠️ 不加--cached的 git rm 会直接删除你电脑上的本地文件！

七、撤销/回滚救命命令

1. 取消add（已经git add，但还没commit）

作用：把暂存区改动撤回工作区，代码改动保留，仅仅取消add

2. 丢弃未暂存的本地修改（恢复文件到上次commit版本）

⚠️ 本地未保存修改直接丢失，改错文件时用来恢复。

3. 重置本地仓库到指定提交（高危！）

--hard：丢弃所有本地未提交修改，文件直接回退到该提交版本，谨慎使用

commit哈希从 git log --oneline 获取7位字符

✅ 单人练习仓库完整标准工作流（从0到上传Github）

仅第一次覆盖远程旧代码才使用 git push -f origin master，后续不要再加 -f

⚠️ 避坑清单

  1. 切换分支会替换本地文件夹文件，未提交代码先commit保存
  2. -f强制推送、git reset --hard高危，多人项目严禁
  3. .gitignore对已经提交到git的文件无效，要用git rm --cached
  4. 远程分支、本地分支相互独立：删除远程分支不会自动删除本地分支
  5. 配置邮箱必须是Github绑定邮箱，提交记录才会正常在Github主页展示
