async-await学习 和 事件循环

2026/5/9 front-end ES6

写在前面：今天了解了“函数”和“方法”的区别，之前的有些说法可能有些不合适，今后改。

  • 函数（Function）：
    • 一个独立代码块，不属于任何类和对象
    • 通过接收参数输入，处理，返回结果
    • 在面向过程编程中比较多
    • 一般是 函数名(参数)
  • 方法（Method）
    • 本质和函数差不多
    • 但是依赖于特定的类和对象
    • 在面向对象编程中比较多
    • 一般是 对象（或类）.方法名(参数)

async和await学习

async和await的语法和返回值

  • async用于修饰函数，被修饰的函数会返回一个Promise对象（就是一个标记，表示可以被await暂停）
    • 语法： async function function() { ... }
    • 该关键字只能加在函数前面（普通函数，箭头函数和类方法都可以）
    • 因为会返回一个 Promise 对象，所以async函数可以用 .then()、.catch() 链式调用
    • 可以在另一个 async函数 里，用 await 来调用
  • await只能在 async函数里面调用，会让代码在该行 “暂停” ，等后面的Promise “成功” 再继续。
    • 语法：
      • 后跟Promise： let res1 = await Promise.resolve("成功处理") ， 等resolve处理
      • 后跟普通值： let res2 = await 'abc' ,等价于await Promise.resolve('abc');
      • 后跟函数调用： let res3 = await(() => '函数返回值')() ,会先执行函数，再await函数返回值
    • 在 async 函数里，执行到 await 会暂停后面的函数，把处理交给浏览器，继续去执行同步任务。 await 后面的函数会变成微任务，存入任务栈。fa

事件循环（Event-Loop）

浏览器事件循环把任务分成以下几类：

  • 同步任务
  • 异步任务
    • 宏任务
    • 微任务

执行顺序（自上而下）：

  • 同步任务1
  • 同步任务2
  • 同步任务3
  • script的微任务
  • （script也是一个宏任务，所以会先执行代码里的其他微任务（在script这个宏任务下））
  • 宏任务1
    • 微任务1
    • 微任务2
    • 微任务3
  • 宏任务2
    • 微任务1
    • 微任务2
    • 微任务3
  • （后续任务。。。）

先执行完同步任务，再执行异步任务。
遇到宏任务，执行完里面的微任务，再执行下一个宏任务。

示意图：

  • 遇到宏任务，把宏任务加入宏任务队列
  • 该宏任务放入回调栈
  • 然后把宏任务里面的微任务加入微任务队列
  • 把当前微任务队列里的微任务FIFO放入回调栈，执行清空回调栈里的微任务
  • 取下一个宏任务，循环以上步骤
